# 账本与持久化实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把「取回来的数据」变成「我的持仓」——存流水、推导持仓与成本、并在份额对不上时**拦住你而不是悄悄改账**。

**Architecture:** 推导是纯函数，进 `packages/core/src/ledger/`（能手算验证，不用起数据库）；持久化有 IO，进 `apps/server/src/`（Drizzle + `node:sqlite`，`sqlite-proxy` 适配器）。两边单向依赖：`apps/server → core`。

**Tech Stack:** TypeScript 7（strict，ESM）· Vitest 5 · Drizzle + `node:sqlite`（`sqlite-proxy`）· Node 24 原生执行 `.ts`

**Spec:** `docs/superpowers/specs/2026-11-19-ledger-design.md`（权威设计，**动手前必读**）

## Global Constraints

- TypeScript strict，ESM；**不使用装饰器**；**相对导入必须带 `.ts` 后缀**
- **`packages/core` 保持纯函数**：不 import 任何框架、不做 IO、**不读时钟**（§二 规则 3）
- **`core` 不写算式之外的东西**：金额/份额比较一律 `approxEqual`，**禁止 `===`**（§8.1）
- **业务日期只许 `YYYY-MM-DD` 字符串**；不要引入 UTC 转换（§8.2）
- **错误分类**（§8.3）：数学/数据上无解 → `null`；参数非法 → 抛异常；数据缺失 → `null`
- **包的出口用显式列名导出，不用 `export *`**（§8.4）
- **测试要短**（§8.10，硬要求）：造数据用助手函数、**不写 `describe` 包裹**、同类断言合并进同一个 `it`；测试名中文
- **测试要克制**（§8.8）：判据只有一条——**这条路径会不会在真实使用中静默产生错值**
- **最简优先**（§9.5）：少一层间接、少一个接口、少一个可配项。**但「简」指结构不指做工**——命名、注释、错误分类、边界处理一律不打折
- 注释解释「为什么」，不复述「做什么」；标识符英文、注释与用户可见文案中文
- **提交信息不得包含任何工具署名行**；提交只 `git add` 本任务文件，**禁止 `git add -A`**
- **推导一律只吃 `status === 'confirmed'` 的流水**——这是契约的一部分，不是优化

## Review Focus

规格未逐一写明、但最可能在实际使用中咬人的五类。**每条都在所属任务里配了测试。**

1. **成本口径实现错**：赎回要**按比例结转**（单位成本不变），不是冲减成本；红利再投要**按两步展开**（分红记已实现收益 + 按再投净值买入）。错了两个数字都「看着合理」，而盈亏是给人做决策用的
2. **`pending` 流水被静默算进持仓**：计划 5 会塞进待确认的分红/折算。不按 `status` 过滤，它们就会被当成已入账的份额
3. **份额折算的量纲**：`splitRatio` 是**比例**（`1:0.3709` → 乘 `0.37094933`），不是份额增减量。存错量纲，份额与成本立刻全错
4. **对账漏掉补录的流水**：用户事后补录一笔**早于上次对账日**的流水时，任何「增量」实现都会漏。**本计划要求每次全量重推**
5. **成本缺失被编成数字**：没有买入记录时成本必须为 `null`，**不能编 0 或某个数**。§6：此时只做风险跟踪、不显示个人盈亏

### Task 2: 成本与已实现收益（移动加权平均）

**Interfaces:**

**口径（设计 §八，使用者 2026-11-19 定，不要自行改）：**

| 事件 | 份额 | 总成本 | 已实现收益 |
|---|---|---|---|
| 申购 | + | + 买入金额（含申购费） | — |
| 赎回 | − | **按比例结转**（单位成本不变） | + (卖出回款 − 结转成本)，赎回费从回款扣 |
| 现金分红 | 0 | **不变** | **+ 分红金额** |
| 红利再投 | + | **+ 再投金额** | 先记 + 分红金额，再按再投净值买入 |
| 份额折算 | 按 `splitRatio` 乘 | **不变** | — |
| 费用 | 0 | 计入对应买卖的成本 | — |

- [ ] **Step 2: 跑测试确认失败** → **Step 3: 实现成本计算**

要点（签名与测试已定的不再重复）：

- **赎回按比例结转**：`结转成本 = 总成本 × (赎出份额 / 赎出前份额)`；卖出回款减结转成本进 `realizedGain`。**不是**从成本里扣掉回款
- **红利再投**：`amount` 存的是**再投金额**（正数），推导时按「分红记 `realizedGain`、同额买入摊进成本」
- **成本未知**：一旦总成本为 `null`（从未有买入记录），后续买入要**恢复**它；纯分红/折算不会凭空造出成本
- `amount` 的符号约定（写进 `types.ts` 注释）：**流向账本为正**（赎回、现金分红），**流出为负**（申购、费用）
- 单位成本 = 总成本 / 份额（`shares` 为 0 时见下）

### Task 6: 三个 Repository

**Files:**

**Interfaces:**

  - `createTransactionRepository(db)` → `{ add(tx): Promise<void>; listByFund(ledgerId, fundCode): Promise<LedgerTransaction[]>; listAll(ledgerId): Promise<LedgerTransaction[]>; setStatus(id, status): Promise<void> }`
  - `createReconcileRepository(db)` → `{ add(ledgerId, fundCode, result): Promise<void>; lastMatchedAt(ledgerId, fundCode): Promise<string | null> }`

- [ ] **Step 1: 写失败的测试（用 `:memory:` 库，不 mock 数据库）**

```ts
const fresh = () => {
  const { db } = openDatabase()
  return { db, ledger: createLedgerRepository(db), txs: createTransactionRepository(db) }
}

it('账本存了能取回，且能列全部', async () => {
  const { ledger } = fresh()
  const id = await ledger.create('实盘')
  expect((await ledger.get(id))?.name).toBe('实盘')
  expect(await ledger.list()).toHaveLength(1)
})

it('流水按基金取回，含 pending 的（过滤是推导层的事）', async () => {
  const { ledger, txs } = fresh()
  const id = await ledger.create('实盘')
  await txs.add({ ...tx('2026-01-05', 'subscribe', { sharesDelta: 1000, amount: -1000 }), ledgerId: id })
  await txs.add({ ...tx('2026-01-06', 'dividend_cash', { amount: 50, status: 'pending' }), ledgerId: id })
  expect(await txs.listByFund(id, '000001')).toHaveLength(2)
})

it('能改状态（待确认 → 已确认）', async () => {
  const { ledger, txs } = fresh()
  const id = await ledger.create('实盘')
  await txs.add({ ...tx('2026-01-06', 'dividend_cash', { amount: 50, status: 'pending' }), ledgerId: id })
  await txs.setStatus(`${'2026-01-06'}-dividend_cash`, 'confirmed')
  expect((await txs.listByFund(id, '000001'))[0]!.status).toBe('confirmed')
})

it('没对过账时 lastMatchedAt 是 null', async () => {
  const { ledger, db } = fresh()
  const id = await ledger.create('实盘')
  expect(await createReconcileRepository(db).lastMatchedAt(id, '000001')).toBeNull()
})
```

- [ ] **Step 2–4: 跑测试确认失败 → 实现 → 跑测试确认通过**

**`listByFund` 不过滤 `status`**：过滤是推导层（`core/ledger`）的责任，Repository 只管存取。这一点写进注释——**两处都过滤会让「待确认」这种数据在上层凭空消失**。

**Files:**
- Create: `apps/server/src/repository/sqliteCacheStore.ts`、`sqliteCacheStore.test.ts`
- Modify: `apps/server/src/db/schema.ts`（加 `cache` 表）

**Interfaces:**
- Consumes: Task 5 的 `AppDatabase`；`@fundmanager/datasource` 的 `CacheStore` / `CacheEntry`
- Produces: `createSqliteCacheStore(db): CacheStore`

- [ ] **Step 1: 写失败的测试**

```ts
it('存了能取回，信封字段一个不丢', async () => {
  const s = createSqliteCacheStore(openDatabase().db)
  const e = { value: [1, 2], source: 'f10/lsjz', dataAsOf: '2026-11-18', capturedAt: '2026-11-19T10:00:00+08:00', expiresAt: 9999999999999 }
  await s.set('nav:000001', e)
  expect(await s.get('nav:000001')).toEqual(e)
})

it('没存过取回 undefined', async () => {
  expect(await createSqliteCacheStore(openDatabase().db).get('nope')).toBeUndefined()
})

it('已过期仍能取回——降级要靠它拿旧值', async () => {
  const s = createSqliteCacheStore(openDatabase().db)
  await s.set('k', { value: 1, source: 'x', dataAsOf: '2026-01-01', capturedAt: '2026-01-01T00:00:00+08:00', expiresAt: 1 })
  expect(await s.get('k')).toBeDefined()
})
```

- [ ] **Step 2–4: 跑测试确认失败 → 实现 → 跑测试确认通过**

`cache` 表：`key` 主键 + `value`（JSON 串）+ 信封各字段的列。**`get` 绝不判断过期**——这条语义与 `MemoryCacheStore` 逐字一致（过期项正是降级唯一的旧值来源）。**不要把 JSON 存成 blob**，存文本便于排障。

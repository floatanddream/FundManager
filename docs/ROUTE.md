# 通往 MVP 的路线

> 2026-11-18 立。本文件是**路线图**，不是计划本身——每份计划各自有文件。
> **维护约定：** 计划状态一变就改第二节那张表；新增计划就加一行。别在这里复述计划的细节。

## 一、终点：MVP 是什么

判据是**能看见的东西**，不是「代码写完了」：

1. 能手录一只基金的一笔买入，账本记下流水
2. 能看到这笔持仓的**真实净值走势**——不是手算的数字
3. 能看到**穿透后的行业暴露**，且界面同时标注了**数据口径与数据时点**（缺一即误导）
4. 能看到组合层面的**风险评估**，以及**带归因的预警**（反目标 A2：不归因的预警两周内会被全部屏蔽，系统价值归零）
5. 全程**没有一次静默使用陈旧数据**——旧就标出来

**不含**：下单、涨跌预测、多用户托管。这三条是项目边界，不是「还没做」。

## 二、路线

| # | 计划 | 状态 | 依赖 | 关键产出 |
|---|---|---|---|---|
| 1 | core 契约与收益 | ✅ **完成** | — | 三种价格类型编译期隔离；`normalizeFlows` / `npv` / `xirr` / `timeWeightedReturn` |
| 3 | **数据源层** | ✅ **完成** | 1 | 20 个端点；按能力取数；缓存与降级；`stale`（数据旧）与 `loss`（口径弱）两个标记；fixture 与契约测试两层 |
| 4 | **账本与持久化** | ⬜ 未写 | 1 | 流水表、持仓推导、份额折算、一致性检查（不自动改账）、`node:sqlite` + Drizzle proxy 适配器 |
| 2 | core 风险指标 | 📝 **已写未跑** | 1 | 年化/下行波动、最大回撤与修复期、滚动持有收益分布、相关性矩阵 |
| 5 | 估值与归因 + API + 预警 | ⬜ 未写 | 2, 3, 4 | 持仓拼接估算（每条带报告期/覆盖比例/算法名）、穿透、组合风险、归因式预警、Fastify 服务 |
| 6 | 前端界面与图表 | ⬜ 未写 | 5 | React + Vite + shadcn/ui + ECharts |

```
1 ─┬─> 3 ─┐
   ├─> 4 ─┼─> 5 ─> 6
   └─> 2 ─┘        ← 计划 2 不在关键路径
```

## 三、为什么是这个顺序

- **3 排在 4 之前。** `core` 至今是对着手算数字在算——没有一只真基金进来过。先有真数据，账本才有东西可对账
- **2 不在关键路径。** 波动率、最大回撤、相关性全要真实净值序列才有意义，而那要等 3。计划 2 算完也看不见东西。**但它已经写好、随时能跑**：可作为 3 与 4 之间的填充，或与 3 并行
- **5 必须等 2 + 3 + 4 齐。** 估值要持仓（3）与成本份额（4）；归因要风险指标（2）
- **6 最后。** 没有 5 的 API，界面没数据可取

## 四、不在路线上、但会咬人的

| 事项 | 现状 | 什么时候必须处理 |
|---|---|---|
| **没有 CI** | 类型隔离只靠手动跑 `pnpm typecheck`，忘了就静默失效。仓库目前没有任何 CI 基建 | **建议在计划 4 之前补**——它守护的是本项目唯一的核心安全机制 |
| **计划 2 的测试片段有 9 处 `describe`** | 违反 `CONSTRAINTS/08-code-style.md` §8.10，但计划 2 未执行，文件是惰性的 | **派发计划 2 的 Task 1 之前必须修**，否则立刻产出不合规的测试 |
| **分红/份额折算的自动入账** | 计划 3 已能取到数据，但**能取到 ≠ 能自动记账**：现金分红与红利再投是两种事件，自动判错会让账静默出错 | 计划 4 的范围之一，且**必须用户确认后才入账** |
| **`FHFCBZ` 取值语义** | 只有 2 个样本（`0`=分红、`106`=拆分），未穷举 | 实现分红入账前先扩样本 |
| **计划 6 的三项待定** | API 端口、前端如何得知 API 地址、CORS 配置 | 计划 5 里定 |
| **`feat/core-returns` 这个名字已经不符** | 它现在同时装着 `core` 与 `datasource` 两层 | 合并前可改名，或就让它带着 |

## 五、分支与合并

计划 1、3（及此后的 4/5/6）都在**同一条分支 `feat/core-returns`** 上累积，**未推送到远端**。

**等 MVP 出来再合到 `main`**（使用者 2026-11-18 定）。在此之前不合并、不推送。

| | |
|---|---|

| 下一步 | **计划 4（账本与持久化）**——它才是把数据变成「我的持仓」的那一步；或先跑计划 2（已写好，插在 3 与 4 之间最省事） |

**计划 3 的一条经验（写下一份计划时照着做）：** 盘点和设计里那些「实测结论」，只要有实现者去真实取数复核，就有相当比例被推翻——它们大多是**一个人、一个样本**得出的。所以端点类计划的简报里要写「**别默认盘点是准的**」，并且**覆盖自审必须逐个端点对账，不是按节对账**（计划 3 就漏掉了 `fundmobapi` 整族 4 个端点）。
